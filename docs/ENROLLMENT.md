# 客户端登记协议

[返回 README](../README.md) · [小白使用指南](BEGINNER.md)

本文件描述当前真实服务端与 CLI：`server/application.mjs`、`scripts/certrelay-agent.mjs`。旧 `scripts/dev-server.mjs` 仅用于开发，不是生产入口。

## 操作流程

1. 管理员在主面板创建客户端邀请，填写名称/备注，并选择允许领取的证书。
2. 服务端生成登记链接与独立的 8 位验证码；验证码只在创建响应中显示一次。
3. 在实际客户端运行：

   ```bash
   certrelay-agent enroll --identity /etc/certrelay-agent/identity.json
   ```

4. CLI 提示粘贴邀请链接，从链接获得初始服务端地址，显示目标中心，并隐藏读取验证码。
5. CLI 通过 HTTPS 提交登记编号和验证码；正常校验 CA/主机名，不跟随跨站重定向。
6. 服务端原子验证并消费邀请，返回独立客户端 ID 和长期令牌。
7. CLI 验证响应后保存地址和身份。生产客户端身份文件按 0600 权限保存，已有身份不会被静默覆盖。

服务端地址不是预置的，也不是从未知网络自动发现的。管理员提供的链接是信任引导的一部分，使用前应核对域名。

## 有效期与一次性语义

- 默认生成后十分钟有效，以服务端时间为准；查看链接不延长有效期。
- 链接包含不可预测的 128 bit 登记编号，不包含验证码或长期令牌。
- 验证码采用服务端密钥 HMAC 保存；不能通过读取状态文件取回明文验证码。
- 一份邀请最多成功登记一次。并发正确请求只有一个成功。
- 最多允许五次错误验证码，另有来源和全局流量限制。
- 过期、撤销、锁定、重新生成或已成功使用的旧邀请不能再登记。
- GET 查看登记链接不会消费资格，也不返回验证码。
- 关闭弹窗后不能恢复验证码；未登记邀请可重新生成，旧链接/码随即失效。已登记客户端不再显示同一邀请的重新生成入口。

## 身份与权限

- 每个客户端有独立高熵长期令牌，服务端只保存其哈希。
- 每次心跳、查询清单、下载和回执都验证身份；下载还检查当前证书授权。
- 客户端名称、备注、架构、主机名与来源 IP 用于管理展示，不是身份凭证。
- 身份文件被复制后可被冒用，因此该设计不是硬件绑定或不可克隆证明。
- 撤销客户端身份阻止后续通信，不会远程删除机器已下载的证书或私钥。
- 新增域名不会自动授权给所有客户端。

## 登记不等于安装

登记只建立地址和身份。证书安装还需要：

- 主服务器成功发布生产证书。
- 管理员授权该客户端领取。
- 客户端同步任务实际运行，且本地 Nginx 检查、重载、TLS 验证配置正确。

独立登记不会自动启用定时器。分开安装/登记后执行：

```bash
systemctl enable --now certrelay-agent.timer
systemctl start certrelay-agent.service
```

`installed` 表示新版本安装成功，`verified` 表示已有版本验证成功。心跳成功或面板在线不代表证书落盘。

## 接口概要

| 接口 | 作用 |
| --- | --- |
| POST /api/v1/admin/enrollments | 管理员创建邀请 |
| GET /enroll/{id} | 查看邀请是否有效，不消费 |
| POST /api/v1/enrollments/{id}/claim | 校验验证码并消费邀请 |
| POST /api/v1/agent/heartbeat | 长期令牌心跳 |
| GET /api/v1/agent/manifest | 查询可下载证书清单 |

管理员接口要求登录，修改接口要求 CSRF。生产使用 HTTPS 固定源站，不接受关闭 TLS 校验的登记方式。HTTP 只允许显式启用的本机开发例外。

## 失败处理

网络失败、验证码错误或本地身份保存失败，不应通过覆盖已有身份解决。如果服务端已消费邀请但客户端未收到/保存响应，旧邀请不能恢复令牌；管理员应撤销这次身份，明确重新登记，避免遗留有效身份。

应用不会主动打印令牌；反向代理、调试工具和外部日志系统也应避免记录 Authorization、验证码、请求体或登记响应。

测试入口包括 `npm test` 和可选的 `npm run verify:live-ui`；测试使用临时假凭据，不替代真实 Linux 部署与公网 TLS 验收。
